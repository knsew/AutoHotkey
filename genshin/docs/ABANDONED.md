# 放弃清单（60 帧口径）

口径：Ji 2026-10-30 定——首期只按 60 帧做，60 帧做不了的先放弃，
原因记在这里，不静默丢掉。以后若口径变了（例如改走 120/144 帧解锁），
按每条后面的“重返条件”重新评估，不要直接把文件拷回来就用。

## 已放弃：恰斯卡 6 命全套

来源：ShiyunKong/Genshin-Impact-Chasca-Macro-for-C6

涉及文件（全部不在首期 combos 里）：
- `恰斯卡2236.ahk`（AHK v2，一键序列）
- `恰斯卡11炮266 / 11炮356 / 14炮2236` 的 `.GMAC`、`.jmm` 设备宏
- `恰斯卡P2-v3lua.txt`（罗技 Lua，调用上述设备宏）
- `Armory Crate device profiles/` 下的 ROG 外设配置文件

放弃原因（按 README 原意，非转述臆测）：
1. 该仓库明确写：必须要解锁帧数，恰斯卡在 120 或 144 帧时浮空时间最长，
   高于或低于这个区间都会缩短浮空时间。
2. 它的蓄力循环时序（例如 520ms、1300ms、770ms、980ms 这类按住时长）
   是按 120/144 帧下的浮空时长排的。60 帧下浮空本身就变短，
   蓄力还没按完角色就落地了，整套循环会错位、断档。
3. 这不是“把 Sleep 数字改小就能修”的问题：浮空时长是帧数决定的物理量，
   时序表必须在目标帧数下重新实测重排，60 帧下没有现成的正确时序表。

重返条件（缺一不可）：
- Ji 明确改走 120 或 144 帧解锁路线；
- 在该帧数下重新实测每一发蓄力的按住时长，再入库；
- 设备宏（ROG / Pulsar / 罗技）仍需单独处理，见下一条。

## 已放弃（同套连招的设备版）：恰斯卡设备宏

上面 `.GMAC`、`.jmm`、ROG `.rog`、罗技 Lua 属于同一套恰斯卡连招，
除了 60 帧问题外还有第二个原因：设备锁定。
ROG 配置文件只在 ROG 外设上用，Pulsar 宏只在 Pulsar 外设上用，
罗技 Lua 本身不含时序、只是调用设备里名字叫“恰斯卡 11 炮 / 14 炮”的宏。
本管理器是键盘通用路线，首期不做设备格式解析。

## 明确不是放弃、只是延后（不要和上面混淆）

- 恰斯卡仓库里的胡桃 11az、那维莱特重击旋转：不是帧数问题，
  是作者自己说质量不能保证，且胡桃、那维莱特已有其他来源覆盖，
  因此延后到后期批次，不是不做。
- FogMoe 的开关改写左键模式、AHK-flex 的单体大脚本、BotMek 分享站、
  gcsim 队伍轴：都不是 60 帧做不了，是需要额外的引擎模式或解析器，
  延后到后期批次。
- 兹白：GitHub 上搜不到现成宏，但它的公开手法没有帧数锁定条件，
  因此没有放弃，而是按手法新写、时序标待调，见 `combos/zibai_*.combo`。

## 明确保留在 60 帧口径内的依据

  魈下落循环是毫秒循环，60 帧下入库，待真机验证。
- 兹白：公开手法没有帧数锁定条件，时序是估算，待真机调校。
